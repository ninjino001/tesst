\chapter{Réalisation de l'application}

\section{Introduction}
Ce chapitre présente la phase de réalisation de la plateforme AIMOS. Il détaille les technologies utilisées, les principales interfaces développées pour chaque rôle, le module d'intelligence artificielle et le déploiement en production.

\section{Outils et technologies utilisés}

\subsection{React}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.20\textwidth]{Logos/React logo.png}
    \caption{Logo de React}
\end{figure}
React est une bibliothèque JavaScript développée par Meta pour créer des interfaces utilisateur sous forme de composants réutilisables. Nous l'avons utilisé avec JavaScript (ES6+) pour le frontend de la plateforme, combiné avec la bibliothèque Recharts pour les graphiques.

\subsection{Vite}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.20\textwidth]{Logos/Vite logo.png}
    \caption{Logo de Vite}
\end{figure}
Vite est un outil de build moderne offrant un serveur de développement rapide avec rechargement à chaud (HMR) et un bundling optimisé pour la production. Il a été choisi pour sa rapidité par rapport à Webpack.

\subsection{Python et Django REST Framework}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.20\textwidth]{Logos/Django logo.png}
    \caption{Logo de Django}
\end{figure}
Django est un framework web Python suivant l'architecture MVT. Combiné avec Django REST Framework (DRF), il permet d'exposer des API REST consommées par le frontend React. Le backend est structuré en 7 apps modulaires.

\subsection{PostgreSQL}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.20\textwidth]{Logos/PostgreSQL Logo.png}
    \caption{Logo de PostgreSQL}
\end{figure}
PostgreSQL est le système de gestion de base de données relationnelle utilisé pour stocker l'ensemble des données de la plateforme (équipements, capteurs, mesures, interventions, alertes).

\subsection{Docker}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.20\textwidth]{Logos/Docker logo.png}
    \caption{Logo de Docker}
\end{figure}
Docker permet de conteneuriser chaque service de l'application dans des conteneurs isolés. Docker Compose coordonne l'ensemble et permet de lancer toute la plateforme avec une seule commande.

\subsection{Nginx et Gunicorn}
En production, Nginx sert de reverse proxy et sert les fichiers statiques du frontend React, tandis que Gunicorn remplace le serveur de développement Django avec 3 workers pour gérer les requêtes de manière performante.

\section{Module d'Intelligence Artificielle}

Le module IA implémente un moteur de prédiction de pannes basé sur trois composantes :

\begin{enumerate}
    \item \textbf{Régression linéaire (fenêtre 48h)} : détecte la tendance d'évolution du capteur et estime quand il atteindra le seuil critique (RUL) ;
    \item \textbf{Z-score (fenêtre 6h)} : identifie les comportements anormaux par rapport à la moyenne récente ;
    \item \textbf{Score composite} : agrège les trois dimensions en un score unique :
\end{enumerate}

$$Score = 0.40 \times Proximité + 0.35 \times Dégradation + 0.25 \times Anomalie$$

Les résultats sont catégorisés en quatre niveaux :
\begin{table}[H]
\centering
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{@{}p{0.15\textwidth}p{0.20\textwidth}p{0.55\textwidth}@{}}
\hline
\textbf{Score} & \textbf{Niveau} & \textbf{Signification} \\
\hline
$\geq 0.75$ & Critique & Panne imminente, intervention urgente \\
\hline
$\geq 0.50$ & Élevé & Dégradation importante, planifier une intervention \\
\hline
$\geq 0.25$ & Modéré & Tendance à surveiller \\
\hline
$< 0.25$ & Faible & Fonctionnement normal \\
\hline
\end{tabular}
\caption{Catégorisation des scores de risque}
\end{table}

\section{Déploiement en production}

L'application est déployée en production via Docker Compose avec l'architecture suivante :

\begin{figure}[H]
\centering
\includegraphics[width=0.75\textwidth]{figures/architecture_deploiement.png}
\caption{Architecture de déploiement en production}
\end{figure}

\begin{verbatim}
Port 80 (Nginx)
├── /*        → fichiers React build (statiques)
├── /api/*    → Gunicorn (Django, 3 workers)
├── /media/*  → fichiers uploadés
└── /static/* → fichiers admin Django
\end{verbatim}

Le déploiement se fait sur une machine Linux avec Docker installé, en une seule commande :
\begin{minted}[bgcolor=bg,fontsize=\small]{bash}
docker compose -f docker-compose.production.yml up --build -d
\end{minted}

\section{Conclusion}
Ce chapitre a présenté la réalisation concrète de la plateforme AIMOS, depuis les technologies choisies jusqu'aux interfaces développées pour chaque rôle et le déploiement en production. L'ensemble des fonctionnalités implémentées couvre le cycle complet de la maintenance intelligente : de la surveillance des capteurs à la prédiction des pannes, en passant par la gestion structurée des interventions avec gammes de maintenance.
